The path on the user's computer of the signed package your endpoint security (EDR) vendor supplies for the Cowork workspace VM. Put its signature file beside the file this path points to, named as that file plus `.sig`. Keep both, and every folder above them, where ordinary users cannot write. Each time the workspace VM starts, it checks that signature and, only if it is from the vendor named in `coworkEDRIntegrationVendor`, which you must also set, runs the package's `install.sh` as root to install or update the sensor. The signature covers only the package file, `install.sh` included; what the sensor downloads afterwards, including its own updates, is the vendor's and is not checked by Claude. macOS only.

Claude reads this key only from configuration that only an administrator can install: an MDM profile on macOS, or the root-owned file under `/etc/claude-desktop` on Linux. It ignores the key in the in-app Setup panel, in any file the user can edit, and from a configuration server. It is one of the app-behavior keys (`disableAutoUpdates`, `relaunchEnforcementHours`, `egressProxyUrl`, …), which Claude takes as a set: once your profile sets any of them, values for the others from a local file or a configuration server stop applying, so put every one you use in the same profile.

Unset (default): no vendor package is installed in the workspace VM. Removing this key only stops later runs of the package. It does not remove or stop a sensor already installed, which stays on the workspace VM's disk until that VM is deleted or replaced.

Network access: `install.sh` and whatever it installs run as root in the workspace VM and are not part of any session, so the network egress allowlist, the proxy keys (`egressProxyUrl`, `egressProxyPacUrl`) and the device's proxy settings do not apply to them. Claude does not otherwise limit which internet hosts they can reach; their connections are ordinary traffic from the device, subject to your own network-layer controls.
