The subset of Claude Desktop managed configuration an Anthropic-hosted (hybrid) config server may store — generated from buildHybridServableSchema(); regenerate with `yarn workspace @ant/managed-config gen:hybrid-servable`, never hand-edit. Structural contract only: objects are closed (unknown keys rejected), except a node marked `x-opaque: true`, whose members its reading client judges (a store keeps that subtree as JSON, not as a string map, and is the only check for a credential in it: none of the rules below reach inside it); enums/union arms are exact, and every array carries the store's `maxItems` bound (a storage limit the device parse does not apply), but string-hygiene checks the runtime schema applies through refinements — URLs carrying userinfo, unsafe helper-script paths, secret-shaped values, the loopback/https rules beyond the one marker below — are NOT expressible here and are enforced by the consumers (the desktop intake and the admin form). Credentials at rest, 1P-only keys and trust roots are absent by construction. A `format: uri` leaf marked `x-hybridLoopback` may also point at the member's own machine, as it may from a device-managed tier: a URL whose host, as written in the URL's authority, is literally one of its `hosts` (RFC 3986 host; names compared case-insensitively, an IPv6 literal in its brackets), over https or plain http, is applied. Spellings a URL parser merely canonicalises to one of them (a trailing dot, IPv4 shorthand such as `127.1`, decimal or hex, IPv4-mapped IPv6) are outside this contract: a store refuses them even though a device may still apply some. Any other loopback host, and plain http anywhere else, is dropped, and every other URL leaf stays https to a non-loopback host. A leaf marked `x-hybridDerived: true` is computed by the control plane from the organization and stamped on every serve; the server drops an authored value on write and reads this set from the artifact. A leaf marked `x-groupOverride` may also appear in a per-group override entry: `verbatim` with this node's own schema (scalars and arrays replace the organization's value for its members; object-valued settings merge key by key, so a group can add or override keys but not remove one), `nameSubset` as an array naming a subset of the organization's list at this node, each entry at most once: an element is an entry's name, or, where the node also carries `x-groupItemOverride` (an object schema: the entry's name plus the item fields a group may restate), an object of that schema, whose restated fields are laid over the selected entry's own the way a `verbatim` leaf is laid over the organization's value (an object-valued field such as `toolPolicy` merges key by key: the group adds or changes a key and cannot remove one). `x-readers` names the clients that read a leaf (${…}); a leaf without it is read by the desktop only. The marker is per key: which providers or credential arms a client supports is that client's own list (a leaf shared by several arms is marked on each, and so is the `provider` or `kind` constant that selects each arm). `generated/hybridReaderSlice.<reader>.schema.json` is this schema projected on those marks, with the envelope each client is served. `x-formerPaths` lists the dotted paths a hosted schema declared and this one no longer does; a store drops a value at one of them from a write instead of refusing the write. `x-executionTarget` names the only execution target a leaf applies under (`desktop` = the app runs sessions on the device; any other value names the cluster that configures that target); a leaf without it applies under every target.
