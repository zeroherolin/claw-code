Set through your device management (MDM or machine policy) to the UUID of the organization your users sign in to; a value in a user's own configuration file is ignored. After a user signs in to that organization in Claude Desktop on a computer where an earlier third-party configuration of Claude Desktop left chats, Cowork tasks or Code sessions, the app copies them into the user's first-party profile on the same computer; once the user resumes a copied session it behaves like any other first-party session. The copy also uploads the skills the user saved in that third-party configuration (under this organization or none) to their own skills in the organization, only where the organization lets members create skills and scans uploaded skills; otherwise nothing is uploaded. A skill whose SKILL.md declares hooks or tool permissions, or whose folder holds plugin files, is never uploaded. Where that configuration has local MCP servers, the app shows one notification offering to review them in Settings › Import; no server is added without the user's confirmation there. If Anthropic has enabled memory import, that configuration's Cowork memory notes come too, unless the user had paused memory: used at once without review, never overwriting a note, synced like other Cowork memory. Chats, tasks and sessions themselves are not uploaded. The copy runs in the background, once per account and organization, and leaves the originals in place. Without this key, the organization's own setting (Admin settings in claude.ai) decides, and a deployed key takes precedence over it. A value that is not a UUID is reported as a configuration error and copies nothing; one that names a different organization than the one signed in copies nothing and is noted in the app's log. Like other first-party keys, deploying it puts the app's configuration under management, so a third-party connection a user set up in the app's own settings no longer applies. Anthropic can switch the copy off remotely.
