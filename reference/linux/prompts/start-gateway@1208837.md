Under device-delivered configuration (device management, a configuration file or a bootstrap URL) this runs only when set to `true`; for organizations managed from the Claude admin console (the hosted configuration) it is on unless an admin turns it off there. When the app launches under this organization, it copies this computer's earlier third-party sessions into its session store in the background, with Settings → Import's importer (originals stay in place). It lists the earlier configuration's Cowork artifacts in this organization. Optional plugins the user had on come back if still offered: those from the organization plugins directory are switched on, and those from an optional `allowedPluginMarketplaces` entry on the gateway's or bootstrap server's own origin are installed again without asking. Plugins the user uploaded (unless `userPluginUploadsEnabled` is off; they can run programs on this computer) and skills they saved (unless `skillCreationEnabled` is off) are installed again without asking, on or off as they were; a skill that declares tools, hooks, metadata or unknown settings arrives off. Other marketplaces' plugins stay behind. Earlier Cowork projects are added, their instructions held until the user accepts them. The user's Cowork memory and global instructions are copied and used at once, unreviewed (no memory if it was paused). Earlier scheduled tasks are added, each on or off as it was: one that was on runs at its next scheduled time. Runs at most once per device under device-delivered configuration and once more after it joins the hosted configuration. Under the hosted configuration it takes sessions from any earlier device configuration (including ones a console sign-in created) but never those stored under another organization's hosted configuration; under device-delivered configuration, only those stored while no organization ID was configured, and only once one is. Turn on `enabled` too so users can import sessions it leaves out by hand.
