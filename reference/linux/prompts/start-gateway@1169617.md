The ID of the endpoint security (EDR) vendor that signed the package `coworkEDRIntegration` points to: 1 to 32 characters from a to z, 0 to 9 and the hyphen, not starting with a hyphen, for example `example-vendor`. It must be an ID this release of Claude accepts; ask your vendor which ID to use. Required whenever `coworkEDRIntegration` is set. The workspace VM runs the package only if this vendor signed it; a package signed by anyone else is refused, even another vendor this release of Claude accepts. The signature the VM checks is the `.sig` file described under `coworkEDRIntegration`. macOS only.

Claude reads this key only from the configuration described under `coworkEDRIntegration`, and ignores a value from anywhere else. It is one of the app-behavior keys (see `coworkEDRIntegration`), so put it in the same profile as every other app-behavior key you use.

Unset (default): if `coworkEDRIntegration` is set, nothing is installed, and each time the workspace VM starts `cowork_vm_node.log` in the app's logs folder records the reason, `vendor_not_named`. It records `config_invalid` for a value not of the form above and `vendor_unknown` for an ID this release of Claude does not accept; neither installs anything. To turn the feature off without these entries, remove `coworkEDRIntegration`, not this key. Removing either key only stops later runs: a sensor already installed stays on the workspace VM's disk until that VM is deleted or replaced.
