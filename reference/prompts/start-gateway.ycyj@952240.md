The app sends its session API to this endpoint with the configured credential, and the block's presence makes the whole install self-hosted: no session runs on the device, though the local MCP servers on it (the person's own and the organization's) still start on the device and serve the host's sessions (built-in and remote servers do not; of a plugin's servers, only the local (stdio) MCP servers of a plugin in the organization plugins directory do, unless a managed server has the same name), an inference provider configured beside it is ignored, and every key that only configures on-device sessions (marked `x-executionTarget: desktop`) stops applying — that policy belongs to the infrastructure the sessions run on. The credential is the inference credential keys, read for the endpoint instead: `inferenceCredentialKind` (`external-idp` with `inferenceIdpOidc` and `inferenceIdpAuthFlow`; `helper-script` with `inferenceCredentialHelper` and its leaves; `static` with `selfHostedToken`). Must be `https://` (plain `http://` is read only for a loopback host, from device management or the local configuration file; a settings server may not name a loopback host), with no query string or fragment. While essential telemetry is not blocked, crash and error reports from this install can carry a mark that its sessions run off the device, and true-or-false values and counts that describe what this endpoint offers. The app counts its starts and its failures by kind (crashes, errors, and failures to read settings, sign in, connect to local tools or update). It hands the numbers to this endpoint, if it accepts them, with words from a fixed list, the app's version, and the operating system's name, version and processor. The numbers hold no message, name, path, address or ID. The endpoint can tell whose app sent them. It adds totals to its usage report for Anthropic, if you set one up; what it passes on names nobody. Blocking essential telemetry stops the counting.
