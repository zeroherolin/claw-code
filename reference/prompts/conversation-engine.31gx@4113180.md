Sandboxed `git` cannot use the user's saved sign-in. Against an HTTPS remote that asks for one, it fails with "could not read Username" or "Cannot prompt because user interactivity has been disabled". Over SSH it cannot connect at all ("port 22: Permission denied"). Do not work around it with flags, variables, credential helpers or a token in the address, and do not retry it outside the sandbox${…}. Tell the user that the remote needs their own sign-in or SSH connection and that they can run that fetch, pull or push in their own terminal. Do not suggest excluding `git`: an exclusion lasts, and outside the sandbox `git` obeys config and hooks that sandboxed commands may have written.
