The git repositories Claude Code may work in on this install, in the two git forms a plugin marketplace entry takes: `{"source": "github", "repo": "owner/repo"}`, or `{"source": "git", "url": "https://git.example.com/group/project.git"}` for another Git host. Either may add `ref`, the branch a session starts from (a branch name, not a tag or commit; leave it out for the default branch; a person may type another), and `name`, a label shown for the address (up to 64 characters). A `url` is `https://` with no user name, password, query string or fragment (Azure DevOps shows a clone URL with a user name: leave it out); an address written without a scheme is read as `https://`.

Beta. Today: where Code sessions run on a self-hosted session host, people pick a session's repository from this list and cannot type an address; with no list, or an empty one, none is offered and a session starts in the environment's own workspace. The session host still applies its own policy to what it clones. Where sessions run on the device, the key is accepted and has no effect yet: limiting local folders to those whose `origin` is listed, alongside `allowedWorkspaceFolders`, is planned.

Entries are held to what a session host, the only reader so far, accepts: owner and repository names of letters, numbers and `. _ -` (100 characters each) that must start with a letter or number, a branch name both it and git accept, an address of at most 2048 characters whose path has no percent-escape but `%20`.

Unset: there is no list. Empty, or a value that cannot be read as a list: there are no repositories, so none can be chosen; an unreadable value, or a list with no readable entry, is reported and never treated as unset; an empty list an admin writes stays an empty list on every surface. An entry that cannot be read is left out and reported by its position (the first is 0), with the reason; the other entries, and the rest of the configuration, stand.
